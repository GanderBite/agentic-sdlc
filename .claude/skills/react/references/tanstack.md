# TanStack Router + Query integration

`apps/ui` uses TanStack Router `^1.95.x` for routing and TanStack Query `^5.62.x` for server state. They are wired together at boot.

## Setup

```tsx
// apps/ui/src/main.tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { RouterProvider, createRouter } from '@tanstack/react-router';
import { routeTree } from './routeTree.gen';

const queryClient = new QueryClient({
  defaultOptions: { queries: { staleTime: 30_000, retry: 1 } },
});
const router = createRouter({ routeTree, context: { queryClient } });

declare module '@tanstack/react-router' {
  interface Register { router: typeof router }
}

// render: <QueryClientProvider client={queryClient}><RouterProvider router={router}/></QueryClientProvider>
```

`routeTree.gen.ts` is generated by the Vite plugin. Never edit by hand.

## Query key factories

Co-locate factories in `apps/ui/src/api/queries/<entity>.ts`:

```ts
import { queryOptions } from '@tanstack/react-query';
import { api } from '@/api/client';

export const patientKeys = {
  all: ['patient'] as const,
  detail: (id: string) => ['patient', id] as const,
  list: (filters: PatientFilters) => ['patient', 'list', filters] as const,
};

export const patientQuery = (id: string) =>
  queryOptions({
    queryKey: patientKeys.detail(id),
    queryFn: () => api.patients.get(id),
  });
```

Keys are tuples starting with the entity namespace. `invalidateQueries({ queryKey: ['patient'] })` then invalidates everything under that prefix.

## Route loader + suspense query

The loader warms the cache; the component reads it suspensefully. The browser never sees a loading state because the route waits on the loader.

```tsx
// apps/ui/src/routes/patients/$patientId.tsx
export const Route = createFileRoute('/patients/$patientId')({
  loader: ({ context, params }) =>
    context.queryClient.ensureQueryData(patientQuery(params.patientId)),
  component: PatientRoute,
  errorComponent: ({ error }) => <ErrorPanel error={error} />,
  pendingComponent: () => <PatientSkeleton />,
});

function PatientRoute() {
  const { patientId } = Route.useParams();
  const { data } = useSuspenseQuery(patientQuery(patientId));
  return <PatientPanel patient={data} />;
}
```

`useSuspenseQuery` returns `data` as non-nullable. No need to guard `if (!data) return …`.

## Mutations

```tsx
const update = useMutation({
  mutationFn: (input: UpdatePatientInput) => api.patients.update(input),
  onSuccess: (_, vars) => {
    queryClient.invalidateQueries({ queryKey: patientKeys.detail(vars.id) });
    queryClient.invalidateQueries({ queryKey: patientKeys.all });
  },
});

update.mutate(values);
```

## Optimistic updates

Two patterns:

1. **Query cache write** — `setQueryData` to a snapshot before the request, roll back in `onError`.
2. **`useOptimistic`** — local optimistic state for a single component (see `react-19.md`).

Cache-write pattern:

```tsx
const toggle = useMutation({
  mutationFn: (id: string) => api.patients.toggleArchive(id),
  onMutate: async (id) => {
    await queryClient.cancelQueries({ queryKey: patientKeys.detail(id) });
    const prev = queryClient.getQueryData(patientKeys.detail(id));
    queryClient.setQueryData(patientKeys.detail(id), (old) =>
      old ? { ...old, archived: !old.archived } : old,
    );
    return { prev };
  },
  onError: (_e, id, ctx) => ctx?.prev && queryClient.setQueryData(patientKeys.detail(id), ctx.prev),
  onSettled: (_d, _e, id) => queryClient.invalidateQueries({ queryKey: patientKeys.detail(id) }),
});
```

## Anti-patterns

- Calling `useQuery` for data the route's loader already fetched — use `useSuspenseQuery` with the same options.
- Hand-editing `routeTree.gen.ts`.
- Using `refetch()` from inside another component's `useEffect`. Use `invalidateQueries` from the action that caused the change.
- Stringly-typed search params (`location.search` parsing).
- Defining query keys inline at the call site. Always import from the factory file.
