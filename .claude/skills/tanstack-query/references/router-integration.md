# TanStack Router + Query integration

## Pattern: loader warms cache, component reads suspensefully

The loader runs before the route component renders; it kicks off the fetch and TanStack Router waits for it. The component then reads from the (now-populated) cache with `useSuspenseQuery`. The user never sees a "loading…" flash inside the page — the loader gates the navigation.

```tsx
export const Route = createFileRoute('/patients/$patientId')({
  loader: ({ context, params }) =>
    context.queryClient.ensureQueryData(patientQuery(params.patientId)),
  component: PatientRoute,
  pendingComponent: () => <PatientSkeleton />,
  errorComponent: ({ error }) => <ErrorPanel error={error} />,
});

function PatientRoute() {
  const { patientId } = Route.useParams();
  const { data } = useSuspenseQuery(patientQuery(patientId));   // non-null
  return <PatientPanel patient={data} />;
}
```

`pendingComponent` only renders when the loader exceeds `pendingMs` (default 1000ms).

## Wiring the QueryClient into router context

```ts
// apps/ui/src/main.tsx
const queryClient = new QueryClient({ /* defaults */ });
const router = createRouter({
  routeTree,
  context: { queryClient },                  // available to every loader
});

declare module '@tanstack/react-router' {
  interface Register { router: typeof router }
}
```

The loader signature becomes `({ context, params }) => …` with `context.queryClient` typed.

## `ensureQueryData` vs `prefetchQuery`

- `ensureQueryData(options)` returns a promise that resolves with the data. The router awaits this — if it rejects, the route errors. Use this in loaders.
- `prefetchQuery(options)` returns `Promise<void>`. Useful for warming caches the user is LIKELY to need (hover on a link) but not REQUIRED for the current view.

Rule: in route loaders, always `ensureQueryData`. In hover/intent prefetchers, `prefetchQuery`.

## Parallel loads in one route

When a route needs multiple queries, use `Promise.all`:

```ts
loader: ({ context, params }) =>
  Promise.all([
    context.queryClient.ensureQueryData(patientQuery(params.patientId)),
    context.queryClient.ensureQueryData(patientDocumentsQuery(params.patientId)),
  ]),
```

Each component then reads with its own `useSuspenseQuery(<same factory>)`. Never use `useQueries` for this — the loader has already done the parallelization.

## Search-param-driven queries

```ts
const Search = z.object({
  q: z.string().optional(),
  status: z.enum(['active', 'archived']).optional(),
  page: z.coerce.number().int().min(1).default(1),
});

export const Route = createFileRoute('/patients/')({
  validateSearch: Search.parse,
  loaderDeps: ({ search }) => search,                            // <-- declares dep
  loader: ({ context, deps }) =>
    context.queryClient.ensureQueryData(patientListQuery(deps)),
  component: PatientListRoute,
});
```

`loaderDeps` is the magic: when search params change, the loader re-runs with the new `deps`. Without it the loader would only run on path changes.

In the component:

```tsx
function PatientListRoute() {
  const search = Route.useSearch();
  const { data } = useSuspenseQuery(patientListQuery(search));
  // …
}
```

## Invalidation across navigations

After a mutation, `invalidateQueries({ queryKey })` marks queries stale. The next time a route renders that consumes them, they refetch. If the user is already on that route, the consuming `useSuspenseQuery` triggers a background refetch (no Suspense fallback flash because the cache still has data).

To force the suspense fallback to show again, use `queryClient.resetQueries({ queryKey })` instead. Almost always you want `invalidateQueries`.

## Dependent / conditional queries

Some queries depend on another query's result. Two options:

1. **Parent route fetches A; child route fetches B(a)** — preferred. The router's tree structure already encodes the dependency.
2. **Same component, dependent query** — use `useQuery` (not `useSuspenseQuery`) with `enabled: !!a` and render an inline loading state.

```tsx
const a = useSuspenseQuery(parentQuery(id));
const b = useQuery({ ...childQuery(a.data.relatedId), enabled: !!a.data.relatedId });
```

## Don't

- Don't `useEffect(() => loadData())` — that's the pre-loader anti-pattern.
- Don't hand-edit `routeTree.gen.ts` — it's generated by the Vite plugin.
- Don't share a `useQuery` between a loader and a component via React state — use the cache, that's its job.
